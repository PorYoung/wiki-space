初始化推送未在平台留痕

新建文档库自动初始化仓库后，Gitea 可见建仓与推送记录，但平台「活动」页的版本历史与动态流没有任何体现。本页记录根因、修复内容与验证结果。

日期 2026-09-12 模块 apps/server · scripts 状态 已修复 · 已验证

01 · 现象

Gitea 侧（正常）：新建库自动创建仓库 root/test-wiki、main 分支，并推送提交 9930af44f6「chore: 初始化文档库（4 篇模板文档）」。

平台侧（异常）：项目活动页停在「版本历史」空状态「暂无版本记录」；动态流同样看不到这次初始化与推送。

02 · 根因

  1. 初始化提交没有写版本快照。建库链路把推送结果只写入 sync_jobs（stats.init = true）与审计 audit_logs；而「版本历史」按文档聚合 document_versions，该表没有对应行，页面必然为空。
  2. 自动提交的 hash 从未回填。平台内新建 / 保存文档会真实 commit + push，但返回的 commitHash 只进 sync_jobs；document_versions.commit_hash 从未被写入 —— 修复前全库为 NULL。
  3. 初始化推送没有进动态流。activities 只在建项目时写入一条 create，「同步 / 推送」类事件没有记录（PRD F49 的「同步」维度缺失）。

数据源对应关系：版本历史 ← document_versions（按文档聚合、按时间合并）；活动动态 ← activities（verb 驱动筛选与配色）。修复前这两条链路各缺一段写入，页面因此「无记录」。

03 · 修复

触发动作修复前修复后
建库 + Git 自动初始化推送 版本表无行；动态流只有「创建项目」 每篇模板文档写入 v1 快照（commit_hash = 初始化提交、message = 提交信息、作者 = 建库人）；动态流补一条「同步」记录（meta.init = true）
平台内新建文档（有内容） 无版本快照 落库即生成 v1 快照；推送成功回填 commit_hash
平台内保存文档 版本行 commit_hash 恒为 NULL 推送成功后回填 commit_hash；未填「保存说明」时以 Git 提交信息兜底显示
