02机制与数据流

一次「保存文档」在平台内的完整路径：平台库为事实源，NAS 镜像与 Git 提交为旁路落盘，三者由断言逐环核验。

冲突保护：后保存方收到 409 与「加载最新 / 留在当前」选择，绝不静默覆盖；他人保存实时推送，正在编辑者收到提示并将在保存时进入冲突检测。

05部署与运行

完整步骤见 ewiki/docs/deploy.md；此处为最小运行清单。

  • 设施：docker compose -f deploy/compose.dev.yml up -d（PostgreSQL）；Git 演示可加 Gitea 容器。
  • 依赖与建库：corepack pnpm install → db:migrate → db:seed（迁移 0002_lumpy_joystick.sql 新增 storage_connections / platform_settings / users.last_login_at）。
  • 关键环境变量：DATABASE_URL · JWT_SECRET · ENCRYPTION_KEY · FS_NAS_ROOT（绝对路径，server/worker 一致） · WEB_DIST=../web/dist。
  • 启动：web 构建 pnpm --filter @ewiki/web build，server 3000（API+静态+站点）、realtime 3001（WS）、worker（队列）。
  • 初始管理员：admin@ewiki.local / ewiki-admin（上线后立即重置）。
  • 验收复跑：node scripts/e2e-platform.mjs（幂等，可重复执行）。

07边界与遗留

  • GitLab 方言按 REST v4 完整实现；本地无 GitLab 实例，实测走 Gitea 兼容方言——两者共用同一条「验证 → 建仓/关联 → 克隆 → 自动提交」管线，接真实 GitLab 仅需实例与 Token。
  • 协作机制为「基础同步机制」：版本冲突 409 + 实时互见，不承诺 OT/CRDT 字符级合并（与目标假设一致）。
  • 发布站点按「用户当前姓名」解析存储路径，改名后历史站点目录不自动迁移（已记录，后续加目录别名）。
  • 范围外：LDAP 启用、子域名发布、本地客户端形态、生产级高可用多副本。
  • 修复记录：文档路由原有越权缺口（任何登录用户可读写任意项目文档）已补项目级权限校验；worker 令牌内嵌经核查无缺陷（输出脱敏造成的误判）。
  • 2026-09-10 修订：深化越权核验发现发布配置读取/修改（GET /projects/:id/publish-sites、PATCH /publish-sites/:id）缺少项目级校验，已随同全局系统性补齐 22 处 projectAccess 校验（数据源增删改同步、成员管理、概览/图谱/预览/AI 整理/导入、全局文档与动态流范围过滤）；复验 21/21 通过（两个非成员对私有库 10 类资源均 403，全局三列表零泄露），详见验收记录修订章节。
